1. Norman’s Action Cycle (1988)

Don Norman proposed a psychological model explaining how users interact with systems. It focuses on how people form goals, take actions, and evaluate results.

Norman’s 7 Stages of Action

  1. Forming the Goal – What the user wants to achieve.
  2. Forming the Intention – How the user plans to achieve it.
  3. Specifying the Action – Choosing specific steps.
  4. Executing the Action – Performing physical actions.
  5. Perceiving the System State – Seeing what happened.
  6. Interpreting the System State – Understanding what it means.
  7. Evaluating the Outcome – Checking if the goal was met.

The Gulfs of Interaction

Gulf of Execution: Gap between what the user wants to do and what the system allows them to do.

Gulf of Evaluation: Gap between what the system shows and what the user understands.

Examples of Gulfs

  • ATM shows "Error 404" → user doesn’t know what it means → Gulf of Evaluation
  • User wants to cancel a payment but can’t find the cancel button → Gulf of Execution
  • Microwave has symbols instead of words → user guesses → Gulf of Evaluation

2. GOMS Model (Goals, Operators, Methods, Selection Rules)

GOMS is a task-analysis model. It describes how expert users perform tasks efficiently. It breaks tasks into structured components.

Components of GOMS

  • Goals – What the user wants to achieve.
  • Operators – Basic actions (click, type, press).
  • Methods – Step-by-step procedures to achieve goals.
  • Selection Rules – Rules for choosing between methods.

ATM Example in GOMS

  • Goal: Withdraw cash
  • Method: Insert card → Enter PIN → Select Withdraw → Enter amount
  • Operators: Key presses, button taps
  • Selection Rule: If ATM available → use ATM instead of teller

GOMS assumes the user already knows what to do. It does not model confusion or learning.

3. KLM – Keystroke Level Model

KLM is a predictive model. It estimates how long an expert user will take to complete a task. It focuses only on execution — not planning or understanding.

KLM Operators

  • K – Keystroke or tap
  • P – Pointing to a target
  • H – Homing (move hand to device)
  • M – Mental preparation
  • R – System response time

ATM Example (KLM)

  • [M] Decide to press Withdraw
  • [P] Move finger to button
  • [K] Press button
  • [R] Wait for screen update

KLM assumes: no errors, no hesitation, expert user, and perfect memory.

Summary of Core Differences

  • Norman explains thinking + feedback
  • GOMS explains task structure
  • KLM predicts execution time
